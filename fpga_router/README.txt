Router on the Urbana FPGA (XC7S50-CSGA324)

router_core.v       dot product, bias, compare. 4 clocks
router_frontend.v   123-byte packet -> 16 features (13 popcounts + 3 numbers)
uart_rx.v uart_tx.v 8N1 serial, 115200 baud at 100 MHz
router_top.v        top level: clk_100mhz, uart_rxd, uart_txd, led[15:0]
tb_router.v         testbench, prints PASS or FAIL
urbana_router.xdc   pins. Check them against RealDigital's master XDC
router_fpga.py      host side: shots, standin, export, send
router_params.vh vectors.mem tb_vectors.vh   generated by "export" from model.npz and shots.npz (committed)
rebuild_vectors.log the three commands below and their output

shots.npz and model.npz are not committed. These commands, run from fpga_router/ with the kit's Python environment,
rebuild them, and "export" then writes router_params.vh, vectors.mem and tb_vectors.vh byte for byte as committed
(checked on 2026-11-22, see rebuild_vectors.log):
  python router_fpga.py shots ../challenge-1-ml-decoder-kit 0.004 300 shots.npz    300 Stim shots, X memory, seed 11
  python router_fpga.py standin shots.npz model.npz                                 STAND-IN weights, not a trained router
  python router_fpga.py export model.npz shots.npz

Simulate (must print PASS):
  verilator --binary --timing -Wno-fatal --top-module tb_router -I. tb_router.v router_top.v router_core.v router_frontend.v uart_rx.v uart_tx.v
  ./obj_dir/Vtb_router
New weights (router_v1.npz replaces the stand-in):
  python router_fpga.py export router_v1.npz shots.npz
On the board (needs pyserial, see ../challenge-1-ml-decoder-kit/ml_decoder/requirements.txt):
  python router_fpga.py send COM5 router_v1.npz shots.npz

Reported by the author from a sandbox, with no committed log: the simulation passes on the 300 shots, and Yosys
synthesis gives 1,105 LUTs, 611 flip-flops and 16 DSP slices. Not reproduced since (no Verilator or Yosys here).
Not checked: timing at 100 MHz, the board itself, and "send" (pyserial was only imported).
